01ผืนเวทีเดียว มองได้สี่แบบ

โหมดจอไม่ใช่สไลด์คนละชุด แต่เป็นหน้าต่างคนละบานที่มองผืนเดียวกัน

ทุกหน้าถูกวาดลงผืนกว้าง 11520 × 2160 ซึ่งคือจอ 16:9 ขนาด 3840 × 2160 สามจอเรียงกัน แต่ละช่องมีหน้าที่ของตัวเอง — ซ้ายบอกตำแหน่งในกระบวนการ กลางคือเนื้อหาหลัก ขวาคือป้ายกำกับนิทรรศการ

เบราว์เซอร์ไม่ได้ย่อภาพทีหลัง แต่ใช้ CSS transform: scale() ย่อทั้งเวทีลงให้พอดีจอจริง ตัวอักษรกับเส้นจึงคมทุกความละเอียด ตั้งแต่โน้ตบุ๊กไปจนถึงผนัง 4K สามจอ

02นาฬิกาโลกแทนสายสัญญาณ

หัวใจของระบบ และเหตุผลที่ไม่ต้องมีเซิร์ฟเวอร์คอยสั่งจอ

แต่ละหน้ามีเวลาคงที่ตามชนิดของมัน (หน้าเปิด 14 วินาที · หน้าเทียบภาพ 30 วินาที และอื่น ๆ) ตอนโหลด สไลด์บวกเวลาของทุกหน้าในโหมดนั้นเข้าด้วยกัน แล้วคูณตัวเลขเดียวให้รอบลงตัว 30:00 พอดี ได้เป็นไทม์ไลน์ที่ เหมือนกันเป๊ะทุกเครื่องที่ใช้โหมดเดียวกัน

จากนั้นทุกเครื่องถามคำถามเดียวกัน — นับจาก SYNC_EPOCH (๑ มกราคม ๒๕๖๙) ถึงตอนนี้ผ่านไปกี่มิลลิวินาที หารเอาเศษด้วยความยาวรอบ ก็ได้ตำแหน่งในรอบ แล้วเปิดหน้านั้นที่วินาทีนั้น วิดีโอก็ถูกเลื่อนไปที่ เวลา % ความยาวคลิป ด้วย คลิปยาว 2 วินาทีจึงอยู่เฟรมเดียวกันทุกจอ

ผลพลอยได้ที่สำคัญที่สุด: ไม่มีจุดเดียวที่พังแล้วดับทั้งงาน เน็ตหลุด รีเลย์ล่ม มือถือแบตหมด — จอยังเล่นครบรอบเหมือนเดิม เพราะไม่มีอะไรในเส้นทางนั้นที่จอต้องพึ่ง

03รีเลย์คือทางแทรกคำสั่ง ไม่ใช่ตัวขับสไลด์

ชั้นที่ถอดออกได้ทั้งชั้นโดยสไลด์ไม่รู้สึกอะไร

บางครั้งหน้างานก็ต้องแทรกมือ — มีคนมายืนถามแล้วอยากค้างหน้านั้นไว้ หรืออยากกระโดดไปหน้าที่ต้องการให้ผู้บริหารดู งานนี้จึงมีคอนเทนเนอร์เล็ก ๆ อีกตัว (Node ล้วน ไม่มี dependency) ทำหน้าที่ส่งต่อคำสั่งจากมือถือไปยังจอ

ใช้ SSE ไม่ใช่ WebSocket เพราะจอต้องการแค่ รับ คำสั่ง ส่วนสถานะส่งกลับด้วย POST ธรรมดาก็พอ — SSE เป็น HTTP ปกติ ผ่าน nginx ได้โดยไม่ต้องตั้ง proxy upgrade

พอกด ถัดไป / ย้อน / กระโดดหน้า จอนั้นจะหลุดจากนาฬิกาโลก แล้วเดินเวลาของตัวเองต่อไป ถ้ามีหลายเครื่องจะเริ่มไม่ตรงกัน เสร็จธุระแล้วกด กลับเข้าจังหวะนาฬิกา เพื่อดึงกลับเข้าแถว

กดหนึ่งครั้งแล้วเกิดอะไรขึ้นบ้าง

สังเกตว่า รีเลย์ไม่ตรวจคำสั่งเลย — ไม่รู้ว่าสไลด์มีกี่หน้า ไม่รู้ว่า next แปลว่าอะไร มันแค่หาสายของจอที่ชื่อตรงกับ target แล้วเทข้อความลงไป ความรู้เรื่องสไลด์อยู่ที่จอฝ่ายเดียว เพิ่มคำสั่งใหม่จึงแก้แค่สองที่ — ปุ่มบนมือถือ กับ switch ในจอ

รีเลย์เก็บอะไรได้มาจากไหนหายไปเมื่อไหร่
สาย SSE ของแต่ละจอ จอเปิดค้างไว้ตอนโหลด จอปิดหน้า → ขึ้นออฟไลน์ทันที
สถานะล่าสุดที่จอบอก POST /api/state ทุก 10 วิ และทุกครั้งที่เปลี่ยนหน้า ไม่มีใครใช้ชื่อนั้นเกิน 1 ชม. → ลืมทิ้ง

ทั้งหมดนี้อยู่ในหน่วยความจำ ไม่มีไฟล์ ไม่มีฐานข้อมูล รีสตาร์ตรีเลย์กลางงานได้โดยไม่ต้องแตะจอเลย — จอลองต่อใหม่เองทุก 5 วินาที แล้วรายงานตัวกลับเข้ามาพร้อมสถานะปัจจุบัน

ชุดสไลด์และม่านเปิดงาน

นอกจากชุดหลัก 50 หน้าใน 16:9 หรือ 46 หน้าใน 48:9 ยังมีชุด ม่านเปิดงาน อีกชุดหนึ่ง — ม่านแดงเปล่า ๆ ที่ค้างรอ กด ตั้งม่าน ก่อนพิธี พอถึงเวลากด เปิดม่าน ม่านค่อย ๆ รูดเข้าหาข้างทั้งสองใน 4.2 วินาที เผยหน้าแรกของชุดหลัก ที่เริ่มเดินตั้งแต่ม่านเริ่มแยก ไม่ใช่ภาพนิ่งที่ค่อยขยับตอนม่านเปิดสุด แล้ว ค้างหน้าแรกไว้ รอสแตฟฟ์กดเข้าชุดหลักเอง — ช่วงกล่าวเปิดงาน ยาวไม่เท่ากันทุกครั้ง ปล่อยให้สไลด์เดินหน้าตัดบทประธานไม่ได้

ม่านเป็น เลเยอร์คลุมจอ ไม่ใช่หน้าหนึ่งในรายการ — จำนวนหน้าของโหมด ความยาวรอบ และนาฬิกาโลกไม่เปลี่ยน ชุดใหม่จึงไม่แตะของเดิมเลย และวางไว้นอก #stage ที่ถูกย่อด้วย transform ม่านจึงคลุม “จอจริง” ทั้งบานไม่ว่าจะอยู่โหมดไหน

สองอย่างที่ทำให้สายไม่ตายเงียบ: รีเลย์ส่งคอมเมนต์ : ping ทุก 15 วินาทีกัน proxy ตัดสายที่เงียบเกินไป และตอบ x-accel-buffering: no เพื่อไม่ให้ nginx อมคำสั่งไว้ในบัฟเฟอร์จนไม่ถึงจอ

04เครื่องจำค่าของตัวเอง

แยก URL สาธารณะออกจากจอที่รับคำสั่งหน้างาน

/exhibition/ เปล่าเป็นหน้าสำหรับคนทั่วไป เล่นอิสระในชุดหลัก และเริ่มที่ 16:9 เสมอ โดยไม่ต่อรีเลย์หรืออ่านค่าของจอติดตั้งจาก localStorage ส่วนจอหน้างานเปิดพร้อม ?screen=... แล้วตั้งโหมดและค่าอื่นจากมือถือ เครื่องเก็บค่าไว้เอง ไฟดับหรือรีเฟรชก็กลับมาเหมือนเดิม

  1. query string ชนะเสมอ — ?screen=diis บังคับได้ทันที และจำค่าให้ด้วย
  2. ค่าที่จำไว้ — สิ่งที่ตั้งจากมือถือครั้งก่อน
  3. ค่าตั้งต้นของจอควบคุม — ชื่อ main เมื่อ URL มี query แต่ไม่ได้ส่ง screen
  4. URL เปล่า — สถานะ public · 16:9 · เดินอิสระ · ชุดหลัก

ชื่อจอเป็นชื่อของ เครื่อง ไม่ใช่ของโหมด — เครื่องเดียวที่ขับผนัง 48:9 ยังนับเป็นจอเดียวในสายตารีเลย์ ส่วนเลข 1/2/3 ใน 16:9 เป็นเรื่องของโหมด สลับได้ตลอดโดยชื่อไม่เปลี่ยน

ผนังจำลอง — ข้อยกเว้นที่ไม่จำอะไรเลย

ยังไม่มีจอสามบานให้ซ้อม เปิดสามแท็บบนโน้ตบุ๊กเครื่องเดียวแทนได้ แท็บละ ?group=wall&panel=1|2|3 แต่ละแท็บครอปเวทีกว้าง 11520px เหลือช่องของตัวเอง ลากไปเรียงกันแล้วได้ภาพต่อเนื่องเหมือนผนังจริง

แท็บกลุ่มคือ ข้อยกเว้นเดียวของหัวข้อนี้ — มันไม่อ่านและไม่เขียน localStorage เลยสักตัว เพราะสามแท็บอยู่ origin เดียวกันจึงใช้ที่เก็บก้อนเดียวกัน ถ้ายอมให้เขียน แท็บ 2 จะทับโหมดของแท็บ 1 แล้วแท็บ 3 ทับอีกที ผลคือเปิดมาได้ช่องขวาสามอันเรียงกัน ทุกอย่างของแท็บกลุ่มจึงมาจาก query string ล้วน ๆ และเครื่องเดิมเปิด /exhibition/ เปล่า ๆ ทีหลังก็ยังเป็นจอ main แบบ 16:9 เหมือนไม่มีอะไรเกิดขึ้น

ในสายตารีเลย์นี่คือจอสามตัวชื่อ wall-1 wall-2 wall-3 สายละเส้นตามปกติ ที่เพิ่มเข้ามาคือรีเลย์ยอมให้ target ตรงกับ ชื่อกลุ่ม ได้ด้วย คำสั่งเดียวจึงกระจายถึงครบทุกช่องพร้อมกัน ส่วนหน้า controller ยุบสามแถวให้เหลือแถวเดียว แล้วสรุปสถานะแบบ “ตรงกันทุกช่องเท่านั้นถึงบอก” — ช่องไหนหลุดไปคนละหน้าจะขึ้นว่าไม่ตรงกัน แทนที่จะโชว์เลขหน้าของช่องใดช่องหนึ่งมั่ว ๆ

สองปุ่มที่หายไปตอนคุมผนังจำลอง: เปลี่ยนโหมดจอ จะทำให้สามแท็บกลายเป็นช่องเดียวกันหมด และ เปลี่ยนชื่อจอ จะทำให้ทั้งสามใช้ชื่อเดียวกันแล้วเตะกันเองออกจากรีเลย์จนเหลือสายเดียว ทั้งคู่ถูกปฏิเสธที่ตัวสไลด์ด้วย ไม่ใช่แค่ซ่อนปุ่มบนมือถือ

05ทางที่ไฟล์เดินทางถึงจอ

อิมเมจเดียวจบ ไม่ต้องต่อเน็ตออกไปไหนตอนรัน

วิดีโอ ภาพ ฟอนต์ โลโก้ ทั้งหมดถูกฝังลงอิมเมจตอน build คอนเทนเนอร์ที่รันขึ้นมาจึงไม่ต้องพึ่งเน็ตหรือเครื่องใครเลย ตอบเฉพาะพาธใต้ /exhibition/ นอกนั้น 404 ทั้งหมด

06พังตรงไหนแล้วเห็นเป็นอะไร

อาการที่ต่างกันชี้ไปคนละจุดเสมอ

เห็นแบบนี้อยู่ตรงไหนสไลด์ยังเล่นไหม
แถบจอขึ้น (ไม่ต่อรีเลย์) จอไปไม่ถึงรีเลย์ — คนละ origin หรือรีเลย์ไม่ขึ้น เล่นปกติ
มือถือขึ้น ต่อรีเลย์ไม่ได้ รีเลย์ล่ม หรือ nginx ยังไม่ได้ต่อ /exhibition/api/ เล่นปกติ
มือถือขึ้น ไม่มีจอชื่อนี้ในรีเลย์ ยังไม่ได้เปิดสไลด์ หรือพิมพ์ชื่อจอไม่ตรง เล่นปกติ
มือถือขึ้น ออฟไลน์ · เห็นล่าสุด … จอถูกปิด เน็ตหลุด หรือเบราว์เซอร์ค้าง ต้องไปดูที่เครื่อง
แก้สไลด์แล้วจอยังเห็นของเก่า จอถือ HTML เดิมในหน่วยความจำ กด โหลดใหม่ จากมือถือ
จอเดินไม่ตรงกัน มีคนกดเลื่อนหน้าที่จอนั้น กด กลับเข้าจังหวะนาฬิกา
รายละเอียดระดับโค้ดอยู่ใน README.md ของ repo · ทดสอบด้วย node tests/check-deck.mjs และ node tests/check-control.mjs
