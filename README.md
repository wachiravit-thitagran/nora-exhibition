# AI NORA — สไลด์นิทรรศการ (static HTML)

ไฟล์เดียวจบ: `index.html` — เปิดวนลูปบนจอใหญ่ได้ทันที และอัดเป็นวิดีโอ 4K ได้

## 1. ติดตั้งให้อยู่ที่ `/exhibition`

วางโฟลเดอร์นี้ใน web root ของ ainora.psu.ac.th ให้ได้โครงสร้าง

```
<web root>/exhibition/index.html          สไลด์ 64 หน้า
<web root>/exhibition/frame-picker.html   เครื่องมือเลือกเฟรมท่ารำจากวิดีโอ
<web root>/exhibition/brand/              โลโก้ AI NORA + ฟอนต์ Anuphan
<web root>/exhibition/assets/             ไฟล์สื่อ
```

**โลโก้ผู้สนับสนุน** — ทุกสไลด์มีโลโก้ AI NORA (มุมขวาบน) และแถบโลโก้
สำนักงานศิลปวัฒนธรรมร่วมสมัย · กระทรวงวัฒนธรรม · ม.สงขลานครินทร์ (แถบล่าง)
แทนการเขียนชื่อหน่วยงานเป็นตัวหนังสือ

สไลด์จะ**ดึงโลโก้จากเว็บต้นทางให้เองอยู่แล้ว** ถ้าไม่มีไฟล์ในเครื่อง จึงใช้งานได้ทันที
แต่ควรเก็บลงเครื่องด้วย เพื่อให้เปิดหน้างานได้แม้เน็ตหลุดและอัดวิดีโอ offline ได้ — รันครั้งเดียว:

```sh
sh brand/fetch-logos.sh
```

จะได้ `brand/logo-ocac.png`, `brand/logo-moc.png`, `brand/logo-psu.png`
(ถ้ามีไฟล์เวอร์ชันความละเอียดสูงกว่าอยู่แล้ว วางทับชื่อเดิมได้เลย)

**แบรนด์** — โลโก้ AI NORA (`brand/logo-dark.png` พื้นสว่าง / `brand/logo-light.png` พื้นแดง)
และฟอนต์ Anuphan variable (`brand/Anuphan-var.woff2`, น้ำหนัก 100–700, สัญญาอนุญาต SIL OFL
ดูที่ `brand/Anuphan-OFL.txt`) สีส้ม `#E88B00` ดูดมาจากโลโก้โดยตรง ใช้เป็นสีเน้นทั่วงาน
คู่กับโทนสีเดียวกับหน้าเว็บ ainora.psu.ac.th (ทอง `#D4AF37` · หมึก `#111827` · กระดาษ `#F8FAFC`)

**สระบน + วรรณยุกต์ต้องไม่โดนตัด** — Anuphan วางหมึกของสระซ้อนวรรณยุกต์
(ที่ · นิ่ง · เคลื่อน · ครั้ง) สูงถึง `1.119 em` เหนือเส้นฐาน ขณะที่ ascent ของฟอนต์คือ
`1.025 em` หมึกส่วนบนจึงล้นออกนอกกล่องตัวอักษรเสมอ ปกติเบราว์เซอร์วาดทะลุออกไปได้
แต่จะ **หายไปจริง ๆ** สองกรณี

1. ตัวอักษรระบายสีด้วย `background-clip:text` (หัวเรื่องไล่สีทอง) —
   พื้นหลังวาดได้แค่ในกล่องของตัวเอง หมึกที่ล้นจึงไม่มีสีมาลง
   แก้ด้วย `padding-block:.32em` + `margin-block:-.32em` — พื้นที่ระบายกว้างขึ้น
   แต่กล่องนอกเท่าเดิมเป๊ะ เลย์เอาต์ไม่ขยับสักพิกเซล (ตรวจด้วยการ diff ภาพแล้ว)
2. มีกล่องที่ `overflow:hidden` ครอบอยู่และขอบบนเฉี่ยวหมึกพอดี (เช่นแถบหัวการ์ด)
   แก้ด้วยการเพิ่ม `line-height`

`tests/check-thai.mjs` เดินดูทุก element ในทั้ง 64 หน้าและทั้งสองโหมด
คำนวณว่าหมึกล้นกี่พิกเซลแล้วเทียบกับ padding/ขอบที่ตัด ถ้าเจอที่ไหนล้นเกินจะฟ้องทันที

แล้วเปิด `https://ainora.psu.ac.th/exhibition/`

ถ้าเว็บเป็นแอป (Flask/FastAPI/Django) ไม่ได้เสิร์ฟไฟล์ static ตรง ๆ ให้เพิ่ม static route
ชี้ `/exhibition` มาที่โฟลเดอร์นี้

**สำคัญ:** วิดีโอ 22 คลิปดึงจาก `/videos/{id}/file` แบบ root-relative — ทำงานได้เลย
เมื่ออยู่บนโดเมนเดียวกัน ถ้าจะเปิดจากเครื่องอื่นหรือเปิดแบบ offline ให้แก้บรรทัดเดียวใน
`index.html`:

```js
AINORA_BASE : 'https://ainora.psu.ac.th',
```

## 1.5 ควบคุมจอจากมือถือ (controller)

เปิดหน้า **`/exhibition/control`** จากมือถือที่อยู่ในเครือข่ายเดียวกัน
กรอกชื่อจอที่จะคุม แล้วสั่งได้ทั้ง เล่น/หยุด · ถัดไป/ย้อน · กระโดดไปหน้าที่ N ·
สลับโหมดจอ · เต็มจอ · โหลดใหม่ พร้อมเห็นสถานะทุกจอแบบสด

**คุมทีละจอ · หนึ่งเครื่อง = หนึ่งชื่อ** ไม่มีโหมดสั่งพร้อมกันทุกจอ และไม่มีชื่อแยกซ้าย/กลาง/ขวา
เพราะ 48:9 คือเครื่องเดียวขับทั้งผนัง (เป็นจอเดียวในสายตาของรีเลย์) ส่วน 16:9
ก็กดเลือกเลขจอจากหน้า controller ได้อยู่แล้ว — เลขจอเป็น "โหมด" ไม่ใช่ "ชื่อ"

**ไม่ผูกกับ query string** เปิดทุกเครื่องด้วย `/exhibition/` เปล่า ๆ เหมือนกันหมด
แล้วตั้งชื่อจอ · โหมด · จังหวะเดินหน้า · เส้นแบ่งจอ · อนิเมชัน จากมือถือ
เครื่องจำค่าไว้ใน `localStorage` ของตัวเอง ไฟดับหรือรีเฟรชก็กลับมาเหมือนเดิม
ไม่ต้องเดินไปพิมพ์ URL ยาว ๆ ที่ทุกเครื่องอีก

query string ยังใช้ได้และ **ชนะค่าที่จำไว้เสมอ** เอาไว้บังคับตอนตั้งเครื่องหรือทำ QR

| พารามิเตอร์ | บังคับอะไร |
|---|---|
| `?screen=<ชื่อ>` | ชื่อจอ (และจำไว้ให้ด้วย) |
| `?ultra=1` `?wall=1` `?panel=1\|2\|3` | โหมดจอ |
| `?deck=intro` | ขึ้นม่านรอพิธีเปิด (`?deck=main` = ชุดหลักตามปกติ) |
| `?sync=1` `?sync=0` | จังหวะเดินหน้า |
| `?seam=1` `?seam=0` | เส้นแบ่งจอ |
| `?nomotion=1` | ปิดอนิเมชัน |
| `?ctrl=0` | ไม่ต้องต่อรีเลย์เลย |
| `?kiosk=1` | ซ่อนแถบปุ่มบนสไลด์ |
| `?group=<ชื่อ>` | แท็บนี้เป็นช่องหนึ่งของผนังจำลอง ใช้คู่กับ `?panel=` — ไม่แตะค่าที่จำไว้ ดูหัวข้อ **จำลองผนัง 48:9 ด้วย 3 แท็บ** |
| `?preview=1` | เปิดเป็นภาพตัวอย่าง — ไม่เขียนค่าที่จำไว้ ไม่รายงานตัวกับรีเลย์ ซ่อนแถบปุ่ม (หน้า controller ใช้ `window.__PREVIEW` แทน เพราะ srcdoc ไม่มี query string) |

### ลำดับงานหน้างาน

**๑. เปิดจอ** เปิดเบราว์เซอร์บนแต่ละเครื่องไปที่ URL ของเครื่องนั้น (ตั้ง `?screen=` ให้ชัด)
แล้วกด `F` หรือ `⛶ เต็มจอ` บนแถบควบคุมของสไลด์ ชื่อจอจะอยู่ท้ายแถบ ใช้ยืนยันว่าเปิดถูกเครื่อง

**๒. เปิดหน้าสั่งงาน** มือถือต่อไวไฟวงเดียวกัน เปิด `https://ainora.psu.ac.th/exhibition/control`
บรรทัดบนสุดต้องขึ้น *ต่อรีเลย์แล้ว · จอออนไลน์ N จาก N* ถ้าเลข N ไม่ครบ แปลว่ามีจอที่ยังไม่ได้เปิด
หรือชื่อชนกัน (ดูหัวข้อชื่อจอด้านล่าง)

**๓. กรอกชื่อจอแล้วกด เข้าควบคุม** ปุ่มสั่งงานจะโผล่ต่อเมื่อเลือกจอแล้ว
(กันกดแล้วงงว่าทำไมไม่มีอะไรเกิดขึ้น) หรือกดเลือกจากรายการจอด้านล่างแทนการพิมพ์ก็ได้
การ์ดบนสุดบอกตลอดว่ากำลังคุมจออะไรอยู่ · กด **เปลี่ยนจอ** เพื่อย้ายไปคุมอีกจอ

**๔. เลิกงาน** ไม่ต้องทำอะไร ปิดจอได้เลย สไลด์ไม่มี state ที่ต้องเซฟ

| ปุ่ม | ทำอะไร |
|---|---|
| ชุดหลัก · ตั้งม่าน · เปิดม่าน | ลำดับพิธีเปิดสามจังหวะ ดูหัวข้อ **ชุดสไลด์** ด้านล่าง |
| ⏯ เล่น / หยุด | ค้างหน้าปัจจุบันไว้ กดซ้ำเล่นต่อ — ใช้ตอนมีคนมายืนถาม |
| ◀ ย้อน · ถัดไป ▶ | ขยับทีละหน้า |
| ↻ หน้าแรก | กลับหน้า ๑ |
| กระโดดไปหน้าที่ | พิมพ์เลขหน้า (๑–๖๔) แล้วกด **ไป** |
| ภาพตัวอย่างของจอนี้ | มือถือวาดสไลด์เองตามหน้าและโหมดที่จอรายงานมา (ไม่ได้ถ่ายจากจอจริง) ปิดไว้เป็นค่าเริ่มต้นเพื่อประหยัดเน็ต |
| โหมดจอ | เรียงเหมือนแถบบนตัวสไลด์ — `16:9` / `48:9 แบ่ง 3` แล้วแถว `เดี่ยว / จอ 1 / จอ 2 / จอ 3` โผล่เฉพาะตอนอยู่ในตระกูล 16:9 |
| การเดินเวลา | **ตรงกับเครื่องอื่น** เดินตามนาฬิกากลาง · **เดินอิสระ** ปล่อยให้จอนี้เดินเวลาของตัวเอง |
| เต็มจอ | สลับเต็มจอ — **ขาเข้าสั่งข้ามเครื่องไม่ได้** ดู [ทำไมสั่งเต็มจอแล้วไม่เต็มจอ](#ทำไมสั่งเต็มจอแล้วไม่เต็มจอ) |
| เส้นแบ่งจอ | ขีดเส้นทองตรงรอยต่อจอ ใช้เล็งตอนจัดวางจอจริง |
| อนิเมชัน | เปิด/ปิดการเคลื่อนไหวของสไลด์ |
| เปลี่ยนชื่อจอนี้ | ตั้งชื่อใหม่สด ๆ จอต่อสายใหม่และจำชื่อไว้เอง หน้า controller ย้ายเป้าตามให้ |
| โหลดใหม่ | รีเฟรชหน้า — ใช้หลัง deploy เนื้อหาใหม่ |
| จำลองผนัง 48:9 ด้วย 3 แท็บ | เปิดสามแท็บเป็นผนังเดียวกันบนเครื่องเดียว แล้วคุมรวมเป็นแถวเดียว — ดูหัวข้อ **จำลองผนัง** ด้านล่าง |

> **ภาพตัวอย่างโหลดด้วย `srcdoc` ไม่ใช่ `iframe src`** — `ainora.psu.ac.th` ส่ง
> `Content-Security-Policy: frame-ancestors 'none'` มา การ frame ด้วย `src` จึงถูก
> เบราว์เซอร์บล็อกทั้งที่เป็น origin เดียวกัน (`Framing '…' violates … frame-ancestors 'none'`)
> `srcdoc` ไม่มี HTTP response เป็นของตัวเอง กฎนั้นจึงไม่มีผล และยังเป็น origin
> เดียวกับหน้า controller — เรียก `NORA` ข้างในได้เหมือนเดิม **ไม่ต้องแก้ nginx ของ production**
>
> ใน `srcdoc` ไม่มี query string ให้ใช้ หน้า controller จึงยัด `window.__PREVIEW = true`
> เข้าไปก่อนสคริปต์หลักแทน สไลด์เห็นตัวแปรนี้แล้วจะไม่เขียน `localStorage`
> ไม่รายงานตัวกับรีเลย์ ซ่อนแถบปุ่ม และไม่เดินตามนาฬิกา

### ทำไมสั่งเต็มจอแล้วไม่เต็มจอ

เบราว์เซอร์ยอมให้ `requestFullscreen()` ทำงาน **เฉพาะตอนที่ถูกเรียกต่อเนื่องจากการกด
ของคนที่เครื่องนั้น** ("transient activation" — อายุไม่กี่วินาที ไม่ใช่แตะครั้งเดียวแล้วได้ตลอด)
คำสั่งที่วิ่งมาตามสาย SSE จากหน้า controller ไม่นับเป็นการกด จึงถูกปฏิเสธด้วย
`NotAllowedError` เสมอ — **นี่คือกฎของเบราว์เซอร์ ไม่ใช่บั๊กที่แก้ที่โค้ดได้**
(ขาออกไม่มีข้อจำกัดนี้ สั่ง `full 0` ให้ออกจากเต็มจอข้ามเครื่องได้ตามปกติ)

ระบบจึงทำสองอย่างแทนการแกล้งทำเป็นสำเร็จ

1. **ตั้งท่ารอไว้** — พอโดนปฏิเสธ จอจะขึ้นป้าย *"กดปุ่มใดก็ได้ที่จอนี้ เพื่อเข้าเต็มจอ"*
   แล้วรอ การกดครั้งถัดไปที่เครื่องนั้น (เมาส์ คีย์บอร์ด หรือแตะจอ) จะพาเข้าเต็มจอทันที
   ถ้าไม่มีใครกดภายใน 45 วินาที ป้ายหายเอง ไม่ค้างคาจอทั้งงาน
   ระหว่างรอ จอรายงาน `farm:true` กลับไป หน้า controller ขึ้นคำเตือนบอกสาเหตุให้คนสั่งเห็น

2. **เปิดเบราว์เซอร์แบบเต็มจอมาตั้งแต่แรก** — วิธีที่ควรใช้กับจอผนังที่ไม่มีคนเฝ้า
   พิมพ์ชื่อผนังในการ์ด **จำลองผนัง** แล้วก๊อปคำสั่งของแต่ละช่องไปรันที่เครื่องนั้น

   ```
   chrome --kiosk --user-data-dir=/tmp/nora-1 "https://ainora.psu.ac.th/exhibition/?group=wall&panel=1&kiosk=1"
   ```

   | ตัวเลือก | ผล |
   |---|---|
   | `--kiosk` | เต็มจอสนิท ออกด้วย `Alt+F4` / `Cmd+Q` เท่านั้น — ใช้ตอนเปิดงานจริง |
   | `--start-fullscreen` | เต็มจอแต่ยังเรียกแถบเบราว์เซอร์ได้ — ใช้ตอนตั้งเครื่อง |
   | `--user-data-dir` | แยกโปรไฟล์ ไม่ไปชนโครมที่คนคุมงานเปิดใช้อยู่ |

   สองตัวแรกไม่ได้เรียกผ่าน `requestFullscreen` จึงไม่ติดข้อบังคับเรื่องการกดเลย

ที่ตัวจอเองยังกด `F` หรือ `⛶ เต็มจอ` ได้ตามปกติ (นั่นคือการกดของคนอยู่แล้ว)
และ `F11` ของเบราว์เซอร์ก็ใช้ได้เสมอ

ปุ่มที่ "ติดอยู่" จะไฮไลต์สีทองตามสถานะที่จอรายงานกลับมาจริง ๆ ไม่ใช่ตามปุ่มที่เพิ่งกด
ถ้ามีคนเดินไปกดที่ตัวจอเอง หน้า controller ก็ยังตรงกับความจริง

> **สำคัญ:** พอกด ถัดไป/ย้อน/กระโดด/หน้าแรก จอนั้นจะ **หลุดจากนาฬิกาโลก** และเดินตาม
> เวลาของตัวเองต่อไป — แต่ยังพลิกหน้าพร้อมเพื่อนอยู่ ถ้าคำสั่งนั้นส่งถึงหลายจอพร้อมกัน
> (ดูหัวข้อ **จอเล่นพร้อมกันแค่ไหน** ด้านล่าง) ที่หายไปคือการกลับเข้าตารางเวลาเดิม
> เสร็จธุระแล้วกด **ตรงกับเครื่องอื่น** เพื่อดึงกลับเข้าแถว
> (รายการจอด้านล่างบอกอยู่ว่าจอไหน *ตามนาฬิกา* จอไหน *เดินเอง*)

### จอเล่นพร้อมกันแค่ไหน

สามอย่างที่ทำให้จอหลายบานเล่นตรงกัน — วัดเป็นตัวเลขไว้ใน `tests/check-sync.mjs`

**๑ นาฬิกาโลก** ทุกจอคิดตำแหน่งจากสูตรเดียวกันและนาฬิกาเดียวกัน (`SYNC_EPOCH` + ตาราง `DWELL`)
จึงตรงกันเองโดยไม่ต้องคุยกัน — ใช้ตอนไม่มีใครสั่งอะไร

**๒ คำสั่งพกเวลามาด้วย** รีเลย์ประทับ `at` ลงทุกคำสั่ง ทุกจอได้เลขเดียวกัน
จอจึงนับ “เวลาในหน้า” จากตอนที่คำสั่ง **ออกจากรีเลย์** ไม่ใช่ตอนที่คำสั่ง **มาถึงจอนั้น**
ซึ่งต่างกันจอละหลายสิบ ms — ถ้าไม่หักออก ความต่างนั้นจะติดไปกับตัวจับเวลาแล้วอยู่ยาว
จนกว่าจะเปลี่ยนหน้าครั้งหน้า จอสามบานก็พลิกหน้าเหลื่อมกันไปทั้งรอบ
ม่านเปิดงานหักด้วยวิธีเดียวกัน (`animation-delay` ติดลบ) จึงรูดพร้อมกันเป็นผืนเดียว

**๓ ดึงวิดีโอเข้าจังหวะตลอดเวลา** เดิมจัดตำแหน่งคลิปครั้งเดียวตอนเปลี่ยนหน้า
จอไหนเริ่มเล่นช้ากว่าเพื่อน (ไฟล์ยังบัฟเฟอร์ · ตัวถอดรหัสสะดุด) ก็ช้าอยู่เท่านั้นไปทั้งหน้า
เพราะคลิปตั้ง `loop` ความต่างจึงวนตามไปทุกรอบ — หน้าหนึ่ง 32 วินาที คลิป 2 วินาทีวน 16 รอบ
ตอนนี้ตรวจทุก 250ms แล้วดึงกลับ

| ห่างเท่าไร | ทำอะไร |
|---|---|
| เกิน 250ms | กระโดดไปตำแหน่งที่ถูกเลย (เห็นเป็นภาพสะดุดครั้งเดียว) |
| 60–250ms | เร่ง/หน่วงความเร็วไม่เกิน ±12% ให้ไหลเข้าหากัน กลับเข้าที่ในราว 2 วินาที ตาไม่เห็น |
| ต่ำกว่า 60ms | ปล่อยไว้ — ราว 2 เฟรม ตาแยกไม่ออก และถ้าไล่ละเอียดกว่านี้จะแกว่งไม่หยุด |

ผลที่วัดได้: เวลาเริ่มหน้าห่างกัน **0–2ms** · วิดีโอห่างจากจังหวะของหน้า **ไม่เกิน ~60ms**
· ดันคลิปให้เพี้ยน 400ms แล้วระบบดึงกลับเข้าที่เองภายใน 4 วินาที

> กด **ตรงกับเครื่องอื่น** แล้วจอกระโดดเข้าตำแหน่งตามนาฬิกา **ทันที** ไม่ต้องรอเปลี่ยนหน้า
> (เดิมถ้าบังเอิญยังอยู่หน้าเดียวกัน จะเหมือนกดแล้วไม่มีอะไรเกิดขึ้น ทั้งที่ภาพยังเหลื่อมกันอยู่)

> โหมด **48:9 ยาว** (จอ LED ผืนเดียว) ไม่มีปุ่มบนมือถือ เพราะแถบบนตัวสไลด์ก็ไม่มี
> เปิดด้วย `?wall=1` หรือส่งคำสั่ง `mode` ค่า `wall` เอา

> จอไม่ได้พึ่งรีเลย์ในการเดินหน้า ถ้ามือถือแบตหมดหรือรีเลย์ล่มกลางงาน สไลด์ยังเล่นครบรอบเหมือนเดิม

### อ่านสถานะให้ออก

บรรทัดบนสุดบอกสภาพของ **รีเลย์** ส่วนการ์ดจอบอกสภาพของ **จอนั้น** คนละเรื่องกัน

| เห็นแบบนี้ | แปลว่า | ทำยังไง |
|---|---|---|
| `ต่อรีเลย์แล้ว · จอออนไลน์ 2 จาก 2` | ปกติ | — |
| `ต่อรีเลย์ไม่ได้` / `สายหลุด กำลังต่อใหม่…` | รีเลย์ไม่ขึ้น หรือ nginx ยังไม่ได้ต่อ `/exhibition/api/` | `curl -s https://ainora.psu.ac.th/exhibition/api/healthz` · `docker logs nora-exhibition-web` |
| `ไม่มีจอชื่อนี้ในรีเลย์` | ไม่เคยมีจอชื่อนี้รายงานตัวเลย — ยังไม่ได้เปิดสไลด์ หรือพิมพ์ชื่อไม่ตรง | ดูชื่อจริงที่ท้ายแถบควบคุมของจอ หรือกดเลือกจากรายการจอด้านล่าง |
| `ออฟไลน์ · เห็นล่าสุด 3 นาทีก่อน` | เคยต่อแล้วหายไป — จอถูกปิด เน็ตหลุด หรือเบราว์เซอร์ค้าง | ไปดูที่ตัวเครื่อง |

ที่ **ตัวจอ** เองก็ดูได้ — ท้ายแถบควบคุมของสไลด์จะขึ้น `· diis (ไม่ต่อรีเลย์)`
ถ้าสาย SSE ยังต่อไม่ติด (จอลองใหม่เงียบ ๆ ทุก 5 วินาที) ถ้าขึ้นแค่ `· diis` เฉย ๆ = ต่อติดแล้ว
ใช้แยกได้ทันทีว่าปัญหาอยู่ที่ฝั่งจอหรือฝั่งมือถือ

**ขึ้น `(ไม่ต่อรีเลย์)` แล้วไล่ยังไง** — สองคำสั่งนี้แยกได้ครบทุกกรณี

```sh
curl -s https://ainora.psu.ac.th/exhibition/api/healthz   # ต้องได้ {"ok":true,...}
docker logs nora-exhibition-web --tail 20 | grep relay    # ดู log ของรีเลย์
```

| ผลที่ได้ | สาเหตุ |
|---|---|
| `{"ok":true,…}` แต่จอยังขึ้น `(ไม่ต่อรีเลย์)` | จอเปิดจากคนละ origin — ต้องเปิดจากโดเมนเดียวกับที่มือถือเปิด ไม่ใช่ `file://` หรือ `http://<ip>:10096` |
| `502` | รีเลย์ในคอนเทนเนอร์ไม่ขึ้น — ดู log บรรทัดที่ขึ้นต้นด้วย `[relay]` |
| `404` | nginx ตัวหน้ายังไม่มีบล็อก `^~ /exhibition/` หรือยังไม่ได้ reload |
| ต่อไม่ได้เลย | คอนเทนเนอร์ไม่ขึ้น |

> รีเลย์อยู่ในคอนเทนเนอร์เดียวกับสไลด์ ไม่มี service แยก ไม่มี network ที่ต้องตั้ง
> ถ้าคอนเทนเนอร์ขึ้น รีเลย์ก็ขึ้นด้วยเสมอ และถ้ามันตายกลางทาง สคริปต์ในอิมเมจ
> จะสั่งให้ลุกใหม่เองทุก 2 วินาที โดยไม่กระทบสไลด์

จอที่ปิดหน้าไปจะขึ้น *ออฟไลน์* ทันที (รีเลย์รู้จากสายที่ถูกตัด ไม่ต้องรอหมดเวลา)
และชื่อจอที่ไม่มีใครใช้เกินหนึ่งชั่วโมงจะถูกลบออกจากรายการเอง — สำคัญตรงที่ตอนนี้
เปลี่ยนชื่อจอได้จากมือถือ ชื่อเก่าจะได้ไม่ค้างเป็นซากอยู่ในรายการตลอดไป

### ชุดสไลด์

มีสองชุด สลับได้จากมือถือ

| ชุด | คืออะไร |
|---|---|
| **ชุดหลัก** (`main`) | รายการ 64 หน้าที่วนลูปตามปกติ — ค่าเริ่มต้น |
| **ม่านเปิดงาน** (`intro`) | ม่านแดง + หน้าแรกที่ค้างไว้ใต้ม่าน มีสองสถานะในตัวเอง (ม่านปิด / ม่านเปิดแล้ว) |

**ลำดับพิธีเปิด — สามจังหวะ กดเองทุกจังหวะ**

1. ก่อนงาน กด **ตั้งม่าน** — จอขึ้นม่านแดงเปล่า ๆ ไม่มีโลโก้ไม่มีข้อความ
   หน้าแรกรออยู่ใต้ม่าน หยุดนิ่ง วิดีโอไม่เล่น
2. ถึงเวลา กด **เปิดม่าน** — ม่านค่อย ๆ รูดเข้าหาข้างใน 4.2 วินาที เผยหน้าแรก
   ที่เริ่มเดินตั้งแต่ม่านเริ่มแยก แล้ว **ค้างหน้าแรกไว้อย่างนั้น** ไม่วิ่งต่อเอง
3. จบช่วงกล่าวเปิดงานแล้ว กด **ชุดหลัก** เอง — โชว์ 64 หน้าถึงจะเริ่ม

ที่ไม่ให้ระบบพาเข้าชุดหลักเองหลังเปิดม่าน เพราะช่วงกล่าวเปิดงานยาวไม่เท่ากันทุกครั้ง
ปล่อยให้สไลด์เดินหน้าตัดบทประธานไม่ได้ — หน้า controller จะตีกรอบทองที่ปุ่ม
**ชุดหลัก** ไว้ให้เห็นว่าเป็นขั้นต่อไป และการ์ดสถานะขึ้นว่า *ม่านเปิดแล้ว · ค้างหน้าแรก รอกดชุดหลัก*

สถานะม่านถูกจำไว้ด้วย — ไฟดับหลังเปิดม่านแล้วแต่ยังไม่เริ่มโชว์ เปิดเครื่องมาจะกลับมาที่
"ม่านเปิดแล้ว ค้างหน้าแรก" ไม่ใช่ปิดม่านใหม่ให้ต้องเปิดซ้ำต่อหน้าผู้ชม

ม่านเป็น **เลเยอร์คลุมจอ** ไม่ใช่หน้าหนึ่งในรายการ เลขหน้ายังเป็น 64 หน้าเท่าเดิม
ความยาวรอบและนาฬิกาโลกไม่เปลี่ยน เพิ่มชุดแบบนี้จึงไม่กระทบของเดิมเลย

ชุดที่ใช้ถูกจำไว้เหมือนค่าตั้งอื่น ๆ — ตั้งม่านไว้แล้วไฟดับ เปิดเครื่องมาม่านก็ยังปิดอยู่
พอเปิดม่านแล้วค่าเปลี่ยนเป็นชุดหลัก รีสตาร์ตกลางงานจึงเล่นต่อ ไม่ใช่ปิดม่านใส่ผู้ชม

ผ้าม่านทำด้วย CSS ล้วน ไม่มีไฟล์ภาพ อ้างจากภาพม่านจริงของสถานที่ —
แดงสด ผ้าด้าน **ไม่มีทองเลย** มีแค่รางสีเข้มกับตะขอแขวนด้านบน
จีบเป็นคลื่นกว้างและนุ่ม ไม่ใช่ซี่ถี่คอนทราสต์จัด

จีบเกิดจาก `repeating-linear-gradient` สามชั้นที่คาบหารกันไม่ลงตัว
(300 / 137 / 1130 px) ลายจึงไม่ซ้ำเป็นบล็อกให้จับได้ เหมือนผ้าจริงที่จีบไม่เท่ากันทุกลูก
ตะขออยู่ *ใน* บานม่าน ไม่ได้ติดกับราง เวลารูดจึงเลื่อนและอัดกันไปพร้อมผ้า
ตอนเปิด ม่านจะ "รูดเข้าหาข้างจนจีบอัดกัน" ก่อนหลุดออกนอกจอ ไม่ใช่เลื่อนเป็นแผ่นแข็ง
ใช้เวลา 4.2 วินาที ออกตัวช้าตามความเฉื่อยของผ้าหนัก มี `skewX` ที่ค่อย ๆ เพิ่มแล้วคลายกลับ
(ชายล่างลากตามหลังหัวผ้า) และจีบแต่ละชั้นเลื่อนคนละระยะ จีบจึงไถลผ่านกันเองระหว่างรูด

ม่านกว้างเท่า **ผืนเวทีของโหมดที่เลือกอยู่** — 16:9 ก็เต็มจอ 48:9 ก็คลุมทั้งผนัง
เพราะม่านอยู่ใน `#stage` และถูกย่อด้วย transform เดียวกับสไลด์

> ที่ตัวเครื่องกดปุ่ม `C` ก็ได้ — วนสามจังหวะ ตั้งม่าน → เปิดม่าน → ชุดหลัก
> ไว้ซ้อมลำดับพิธีโดยไม่ต้องหยิบมือถือ

> เปิดม่านแล้วจอจะ **เดินเวลาของตัวเอง** (เริ่มนับจากหน้าแรก) ไม่ใช่กระโดดเข้าจังหวะนาฬิกาโลก
> ถ้าอยากให้กลับไปตรงกับเครื่องอื่น กด **กลับเข้าจังหวะนาฬิกา** หลังพิธีเปิด

### ชื่อจอ

ที่มาของชื่อ เรียงตามลำดับที่ชนะกัน

1. `?screen=<ชื่อ>` ใน URL
2. ชื่อที่ตั้งไว้ครั้งก่อน (จำอยู่ในเครื่องนั้น)
3. `main`

**วิธีที่ตั้งใจให้ใช้** คือเปิด `/exhibition/` เปล่า ๆ แล้วกด **เปลี่ยนชื่อจอนี้**
จากมือถือ จอจะจำชื่อใหม่ไว้เอง ไม่ต้องแตะ URL อีกเลย

ถ้ามีมากกว่าหนึ่งเครื่อง **ต้องตั้งชื่อให้ต่างกัน** ไม่งั้นเครื่องหลังจะเตะเครื่องแรก
ออกจากรีเลย์ (ชื่อซ้ำ = จอเดียวกันในสายตาของรีเลย์) — เครื่องแรกที่เปิดจะชื่อ `main`
เหมือนกันหมด ตั้งชื่อทีละเครื่องตอนติดตั้งครั้งเดียว จบ

ชื่อจอไม่ผูกกับโหมด สลับโหมดทีหลัง (ปุ่มบนแถบ · ปุ่ม `U` · สั่งจากมือถือ) ชื่อไม่เปลี่ยน
และชื่อจอแสดงอยู่ท้ายแถบควบคุมของสไลด์ ตอนตั้งหน้างานจะได้รู้ว่าเครื่องไหนชื่ออะไร

> **ทางลัดหน้างาน** เปิดหน้า controller พร้อมชื่อจอได้เลย
> `/exhibition/control?screen=hall-a` ทำเป็น QR ติดข้างเครื่อง สแกนแล้วเข้าคุมจอนั้นทันที
> ถ้าไม่ใส่ หน้า controller จะจำชื่อจอที่คุมล่าสุดไว้ให้เอง

**สไลด์ยังเป็น static เหมือนเดิม** ไม่ได้เปลี่ยนไปเป็น Next.js หรือมี build step
คำสั่งเดินทางผ่านคอนเทนเนอร์เล็ก ๆ อีกตัว (`control/server.mjs` — Node ล้วน ไม่มี dependency)
ที่ nginx ของสไลด์ proxy ให้ที่ `/exhibition/api/`

| ปลายทาง | ใคร |
|---|---|
| `GET /exhibition/api/events?role=screen&screen=<id>` | จอเปิดสาย SSE รอรับคำสั่ง |
| `GET /exhibition/api/events?role=controller` | หน้า controller รับสถานะจอแบบสด |
| `POST /exhibition/api/cmd` | หน้า controller ส่งคำสั่ง |
| `POST /exhibition/api/state` | จอรายงานสถานะกลับ (ทุก 10 วิ และเมื่อเปลี่ยนหน้า) |

คำสั่งที่ `POST /exhibition/api/cmd` รับ (รูปแบบ `{cmd, arg, target}`)

| `cmd` | `arg` | ทำอะไร |
|---|---|---|
| `play` `pause` `toggle` | — | เล่น / หยุด |
| `next` `prev` `restart` | — | ขยับหน้า (หลุดจากนาฬิกาโลกอัตโนมัติ) |
| `goto` | เลขหน้า | ไปหน้าที่ระบุ |
| `sync` | เว้นว่าง = เข้าจังหวะ · `0` = เดินอิสระ | การเดินเวลา |
| `mode` | `0` `1` `2` `3` `w` `wall` | โหมดจอ (แท็บผนังจำลองไม่รับ) |
| `deck` | `main` `intro` | สลับชุดสไลด์ |
| `curtain` | — | เล่นอนิเมชันเปิดม่าน แล้วค้างหน้าแรกไว้ (ยังอยู่ในชุด intro) |
| `name` | ชื่อใหม่ | เปลี่ยนชื่อจอ (จอต่อสายใหม่และจำไว้เอง · แท็บผนังจำลองไม่รับ) |
| `seam` `motion` | เว้นว่าง = สลับ · `1`/`0` = บังคับ | เส้นแบ่งจอ · อนิเมชัน |
| `full` | เว้นว่าง = สลับ · `1`/`0` = บังคับ | ขาออก (`0`) ได้เสมอ · ขาเข้าเบราว์เซอร์กั้นไว้ จอจะรอการกดที่เครื่องนั้นแล้วรายงาน `farm:true` กลับมา |
| `reload` | — | รีเฟรชหน้า |

`target` คือ **ชื่อจอ** หรือ **ชื่อผนังจำลอง** (ดูหัวข้อถัดไป) · `*` = ทุกจอ
(รีเลย์ยังรองรับ แต่หน้า controller ไม่ใช้แล้ว)
ทุกคำสั่งที่เปลี่ยนค่าตั้งของเครื่องจะถูกจำไว้ใน `localStorage` ของจอนั้น

ใช้ SSE ไม่ใช่ WebSocket เพราะจอต้องการแค่ "รับ" คำสั่ง — เป็น HTTP ปกติ
ผ่าน nginx ได้โดยไม่ต้องตั้ง proxy upgrade และไม่ต้องพึ่ง dependency ภายนอก

**ถ้ารีเลย์ล่มหรือยังไม่ได้ deploy สไลด์ทำงานเหมือนเดิมทุกประการ** — จอยังตรงกันเอง
ด้วยนาฬิกาโลก รีเลย์เป็นแค่ทางให้แทรกคำสั่งเข้ามา ไม่ใช่ตัวขับสไลด์
(ปิดการต่อรีเลย์ด้วย `?ctrl=0`)

### จำลองผนัง 48:9 ด้วย 3 แท็บ

ยังไม่มีจอสามบานให้ลอง หรืออยากซ้อมคิวเปิดม่านบนโน้ตบุ๊กเครื่องเดียว
เปิดสามแท็บให้แต่ละแท็บกินคนละช่องของผนังเดียวกัน แล้ว**สั่งทีเดียวถึงพร้อมกันทั้งสามช่อง**

ในหน้า controller มีการ์ด **จำลองผนัง 48:9 ด้วย 3 แท็บ** อยู่เหนือรายการจอ
ใส่ชื่อผนัง (เช่น `wall`) แล้วกด **เปิด 3 แท็บ** — ถ้าเบราว์เซอร์บล็อกป๊อปอัป
กดลิงก์ **ช่อง 1 · 2 · 3** ใต้ปุ่มทีละอันแทนได้ ผลเหมือนกัน

เปิดเองก็ได้ ลิงก์คือ

```
/exhibition/?group=wall&panel=1&kiosk=1
/exhibition/?group=wall&panel=2&kiosk=1
/exhibition/?group=wall&panel=3&kiosk=1
```

ลากไปคนละจอ (หรือเรียงเป็นสามหน้าต่างบนจอเดียว) กด `F11` ให้เต็มจอ
ได้ภาพต่อเนื่องเหมือนผนัง 48:9 จริง

| ส่วน | ทำอะไร |
|---|---|
| `group=<ชื่อ>` | ผูกสามแท็บเป็นเป้าหมายเดียว และสั่งให้แท็บนี้**ไม่แตะค่าที่จำไว้** |
| `panel=1\|2\|3` | ครอปเวทีกว้าง 11520px ให้เหลือช่องของตัวเอง |
| `kiosk=1` | ซ่อนแถบปุ่มบนสไลด์ ลากไปเต็มจอแล้วสะอาด |

ทั้งสามแท็บตั้งชื่อจอให้ตัวเองเป็น `wall-1` `wall-2` `wall-3` รีเลย์จึงถือสายแยกกันสามเส้น
แต่หน้า controller **ยุบให้เหลือแถวเดียวชื่อ `wall`** ติดป้าย **ผนัง** ไว้ กดเข้าคุมแล้วสั่งได้ตามปกติ
เลื่อนหน้า · เล่น/หยุด · ตั้งม่าน · เปิดม่าน ทุกอย่างถึงครบทั้งสามช่องพร้อมกัน

สองอย่างที่**ตั้งใจปิดไว้**ตอนคุมผนังจำลอง เพราะคำสั่งถึงทั้งสามแท็บพร้อมกัน

- **เปลี่ยนโหมดจอ** — สามแท็บจะกลายเป็นช่องเดียวกันหมด ผนังพังทันที
- **เปลี่ยนชื่อจอ** — ทั้งสามจะใช้ชื่อเดียวกันแล้วเตะกันเองออกจากรีเลย์จนเหลือสายเดียว

ทั้งคู่ถูกปฏิเสธที่ตัวสไลด์ด้วย ไม่ใช่แค่ซ่อนปุ่มบนมือถือ ต้องการช่องอื่นก็ปิดแท็บ
แล้วเปิดใหม่จากการ์ดจำลองผนัง

**แท็บกลุ่มไม่เขียน `localStorage` เลยสักตัว** — สามแท็บอยู่ origin เดียวกันจึงใช้ที่เก็บก้อนเดียวกัน
ถ้ายอมให้เขียน แท็บ 2 จะทับโหมดของแท็บ 1 แล้วแท็บ 3 ทับอีกที ผลคือเปิดมาได้ช่องขวาสามอัน
ทุกอย่างของแท็บกลุ่มจึงมาจาก query string ล้วน ๆ และเครื่องเดิมเปิด `/exhibition/` เปล่า ๆ
ทีหลังก็ยังเป็นจอ `main` แบบ 16:9 เหมือนไม่มีอะไรเกิดขึ้น

แถวผนังสรุปสถานะแบบ **ตรงกันทุกช่องเท่านั้นถึงบอก** ถ้าช่องไหนหลุดไปคนละหน้า
จะขึ้นว่า *ช่องไม่ตรงกัน* แทนเลขหน้ามั่ว ๆ — สั่งไปหน้าใดหน้าหนึ่งก็ดึงกลับเข้าแถว
และ `2/3 ช่อง` แปลว่ามีแท็บหนึ่งปิดไปหรือยังไม่ได้เปิด

> ถ้าต้องแก้เฉพาะช่องเดียวจริง ๆ พิมพ์ชื่อ `wall-2` ในช่องกรอกชื่อจอเข้าคุมตรง ๆ ได้
> (ช่องย่อยไม่โผล่เป็นแถวในรายการ เพราะปกติไม่มีประโยชน์)

### เรื่องการกั้นสิทธิ์

ระบบนี้ใช้ในวงภายในของหน่วยงาน จึง **ไม่มี `allow/deny` และไม่บังคับโทเคน**
เปิด `/exhibition/control` จากมือถือได้เลย ไม่ต้องกรอกอะไร

ถ้าวันหนึ่งต้องเปิดสู่ภายนอกจริง มีสองด่านที่กลับมาเปิดได้

- **จำกัดวงเครือข่าย** — ใส่ `allow`/`deny` ที่ `location ^~ /exhibition/api/`
  ใน `deploy/nginx.conf` (มี `set_real_ip_from` + `real_ip_header` ตั้งไว้ให้แล้ว
  ถ้าไม่มีสองบรรทัดนี้ `$remote_addr` จะเป็น IP ของ docker bridge คือ 172.17.x
  ซึ่งตกในช่วง `172.16.0.0/12` พอดี = อนุญาตทุกคนโดยไม่ตั้งใจ)
- **โทเคน** — ตั้ง `CONTROL_TOKEN` ใน `.env` ข้าง `docker-compose.yml`
  หน้า controller จะขึ้นช่องให้กรอกเอง (อ่านจาก `/api/healthz`) ถ้าไม่ตั้งก็ไม่ขึ้น

คำสั่งที่สั่งได้แย่ที่สุดคือเปลี่ยนหน้าจอ/หยุดเล่น ไม่มีการเข้าถึงข้อมูลหรือรันโค้ด

### Google Analytics

ฝัง gtag.js รหัส `G-PD410XC6GH` ไว้ทั้ง `index.html` และ `control.html`
แต่**ทำงานเฉพาะตอนเป็นจอจริงบนเซิร์ฟเวอร์จริง** — สามกรณีนี้ถูกกันไว้
เพราะทั้งสามเกิดขึ้นจริงในระบบนี้และจะทำให้ตัวเลขผู้ชมเพี้ยน

| กรณี | `window.__GA` | ทำไมต้องกัน |
|---|---|---|
| ภาพตัวอย่างบนหน้า controller | `skip:preview` | เปิดสไลด์ทั้งชุดใน iframe ทุกครั้งที่กดดู สแตฟฟ์กดสิบครั้ง = สิบ pageview |
| เปิดไฟล์ตรง ๆ (`standalone.html`) | `skip:file` | ใช้ตอนรีวิวงาน ไม่ใช่ผู้ชมจริง |
| `localhost` / `127.0.0.1` | `skip:local` | Playwright เปิดหน้านี้หลายสิบรอบทุกบิลด์ |
| อื่น ๆ ทั้งหมด | `on` | ยิงตามปกติ |

เปิด console แล้วพิมพ์ `__GA` ตอบได้ทันทีว่า "ทำไมจอนี้ไม่ขึ้นใน Analytics"
โดยไม่ต้องไล่อ่านโค้ด และ `check-control.mjs` ยืนยันไว้ทั้งฝั่งที่ต้องกัน
และฝั่งที่ต้องยิง (ทดสอบด้วยการหลอก DNS ให้ชื่อโฮสต์ปลอมชี้มาที่เครื่องทดสอบ)

> จอในวงที่ออกเน็ตไม่ได้จะยิงไม่ถึง Google — สคริปต์เป็น `async` จึงไม่บล็อก
> อะไรทั้งสิ้น สไลด์เล่นปกติ แค่ไม่มีข้อมูลเข้า Analytics

### เรื่องแคช (จอ Maxhub Pivot)

จอ Maxhub Pivot เป็น Android WebView ที่เก็บแคชดื้อ แก้สไลด์แล้วรีเฟรชอาจยังเห็นของเก่า
`deploy/nginx.conf` จึงตั้งไว้ว่า **ห้ามใช้ของเก่าโดยไม่ถามทั้งไซต์**

| อะไร | header | ผล |
| --- | --- | --- |
| `index.html`, `control.html`, `/api/*` | `no-store, no-cache, must-revalidate, max-age=0` | ไม่เก็บเลย โหลดใหม่ทุกครั้ง |
| `assets/`, `brand/` | `no-cache, must-revalidate` | เก็บได้ แต่ต้องถามก่อนใช้ทุกครั้ง |

ที่ไฟล์สื่อใช้ `no-cache` ไม่ใช่ `no-store` เพราะ `no-cache` ยังยิง conditional request ได้
ไฟล์ไม่เปลี่ยนก็ตอบ 304 ตัวเปล่า วิดีโอหลายสิบ MB จึงไม่ต้องโหลดซ้ำทุกรอบลูป
แต่พอเปลี่ยนไฟล์เมื่อไหร่ ETag เปลี่ยน จอเห็นทันทีตอนรีเฟรช
(ถ้าใช้ `no-store` กับวิดีโอ จอจะดาวน์โหลดคลิปใหม่ทุกรอบจนภาพกระตุก)

`index.html` กับ `control.html` มี `<meta http-equiv="Cache-Control">` เป็นตัวสำรองไว้ด้วย
เผื่อกรณีเปิดไฟล์ตรง ๆ หรือผ่านพร็อกซีที่ไปตัด header ทิ้ง

> จอที่เปิดค้างไว้อยู่แล้วยังถือ HTML เดิมไว้ในหน่วยความจำ deploy ใหม่แล้วต้องรีเฟรช
> กด **โหลดหน้าใหม่** ในหน้า controller สั่งได้ทุกจอพร้อมกัน ไม่ต้องเดินไปแตะทีละจอ

> ตรวจว่ามาถูก: `curl -sI https://ainora.psu.ac.th/exhibition/ | grep -i cache-control`

**ปุ่มสลับโหมดการแสดงผล** อยู่บนแถบควบคุมด้านล่าง (เลื่อนเมาส์ให้โผล่) กด `U` วนก็ได้
ใช้ได้ทุกที่แม้แก้ URL ไม่ได้ เช่นเปิดในหน้า artifact หรือ iframe

มีสองโหมด — เลือก `16:9` แล้วจะมีปุ่มเลือกจอโผล่มาต่อท้าย

| ปุ่ม | URL | ใช้กับอะไร |
|---|---|---|
| `16:9` → `เดี่ยว` | (ค่าเริ่มต้น) | จอเดียวปกติ / โปรเจกเตอร์ / อัดวิดีโอ 4K |
| `16:9` → `จอ 1` `จอ 2` `จอ 3` | `?panel=1\|2\|3` | เครื่องหนึ่งต่อจอหนึ่งของผัง 3 จอ (ซิงก์ตามนาฬิกาให้เอง) |
| `48:9 แบ่ง 3` | `?ultra=1` | เครื่องเดียวลากยาว 3 จอ จอละ 16:9 |

ปุ่มเลือกจอจะซ่อนเองเมื่อกด `48:9 แบ่ง 3` เพราะโหมดนั้นแสดงครบทั้งสามจออยู่แล้ว

**ยังมีโหมดจอยาวไร้ขอบคั่นอยู่** สำหรับจอ LED ผืนเดียว เปิดด้วย `?wall=1`
หรือกดปุ่ม **48:9 ยาว** ในหน้า controller
(ไม่มีปุ่มแล้ว) ผืนภาพเท่ากับ `48:9 แบ่ง 3` เป๊ะ ต่างกันที่สิ่งที่ควรมี "อันเดียวต่อจอ"
จะไม่ซ้ำ 3 ชุด — เหลือแถบโลโก้ผู้สนับสนุนไว้ซ้ายสุด และโลโก้ AI NORA กับเลขหน้าไว้ขวาสุด

**ความสูงถูกล็อกไว้เท่าหน้าจอพอดี** (`100dvh` + `position:fixed` + `overflow:hidden`
+ `overscroll-behavior:none`) ไม่มีแถบเลื่อนและเลื่อนหน้าจอไม่ได้ในทุกโหมด
ตรวจแล้วว่า `scrollHeight == innerHeight` และ `scrollWidth == innerWidth` ทั้ง 6 โหมด

**เวลาแต่ละหน้าเป็นค่าคงที่** อยู่ในบล็อก `CONFIG.DWELL` ของ `index.html` แก้ตัวเลขที่นั่นที่เดียว
แล้ว `CYCLE_TARGET_SEC: 1800` จะยืด/หดทุกหน้าตามสัดส่วนให้รอบลงตัว 30 นาทีเสมอ
(ใส่ `0` ถ้าจะใช้เวลาตาม `DWELL` ตรง ๆ) — เพราะเวลาคงที่ ไทม์ไลน์จึงเหมือนกันทุกเครื่อง
**ทุกจอซิงก์กันได้แม้ไฟล์สื่อยังไม่ครบ** และคลิปที่สั้นกว่าเวลาหน้าจะวนซ้ำในหน้าเดียว

ถ้าไม่ต้องการปกขั้นตอน ให้แก้ `SHOW_DIVIDERS : false` (เหลือ 79 หน้า)

**ปกขั้นตอนมีกองภาพตัวอย่าง** — จอซ้าย (และครึ่งขวาของโหมด 16:9) วางภาพตัวอย่าง
ของขั้นนั้น 3–4 ใบ เอียงสลับซ้าย-ขวาซ้อนกันเหมือนกองรูปถ่าย ไหลขึ้นมาเรียงทีละใบ
เปลี่ยนภาพได้ที่ `STEP_SAMPLE` ใน `index.html` — `shotO(i)` = ภาพสแกนของท่าที่ i
`shotF(i)` = ภาพที่ฟื้นฟูแล้ว (i นับจาก 0 ตามลำดับใน `PAIRS`) ใส่กี่ใบก็ได้
มุมเอียงและระยะเยื้องอยู่ในตัวแปร `ROT` / `OFF`

**ทุกหน้าบอกขั้นตอนของตัวเอง** — บรรทัดบนเป็น "ขั้นตอนที่ 0X · ชื่อขั้นตอน"
บรรทัดล่างเป็น "0X ชื่อขั้นตอน · ลำดับ/ทั้งหมด" และบันไดขั้นตอนบนจอซ้าย
จะไฮไลต์ขั้นที่กำลังแสดง คนที่เดินเข้ามากลางรอบจึงรู้ได้ทันทีว่าอยู่ตรงไหนของกระบวนการ

### ปิดช่วงที่สื่อยังไม่มา (สำคัญสำหรับงานจริง)

นิทรรศการเปิดให้คนนอกดู ถ้าไฟล์ยังไม่มา หน้านั้นจะขึ้นกล่อง
"อยู่ระหว่างจัดเตรียม" ซ้ำกันหลายสิบหน้า ซึ่งไม่ควรปล่อยขึ้นจอจริง
ให้ปิดช่วงนั้นทิ้งไปเลยด้วยสวิตช์ใน `CONFIG` — รอบการแสดงจะยืดหน้าที่เหลือ
ให้ครบ 30 นาทีเองโดยอัตโนมัติ

| สวิตช์ | ปิดแล้วหายไป | ต้องมีไฟล์อะไรจึงเปิดได้ |

| `SHOW_STUDENT` | 4 หน้า | `assets/students/นักศึกษา-1..4.mp4` |
| `SHOW_CLASSROOM` | 2 หน้า | `assets/students/นักเรียน-1..2.mp4` |

### โหมดผู้ดูแล `?dev=1`

ค่าปกติ (ไม่ใส่อะไร) คือ **โหมดนิทรรศการ** — กล่องที่ยังไม่มีไฟล์จะบอกแค่ว่า
"อยู่ระหว่างจัดเตรียม" ไม่โชว์ path ให้คนดูเห็น
ใส่ `?dev=1` เมื่อกำลังเติมไฟล์ จะเห็นชื่อไฟล์ที่ระบบกำลังหาอยู่บนกล่องนั้น

## 3. สื่อและการขึ้นเซิร์ฟเวอร์

**ทุกอย่างอยู่ในอิมเมจเดียว** — สไลด์ ฟอนต์ โลโก้ ภาพเปรียบเทียบ วิดีโอ ภาพพื้นหลัง

### 3.2 เติมสื่อก่อน build

`assets/videos/` ต้องมีไฟล์ชื่อ `<videoId>.mp4` ครบ 22 ไฟล์ · `deploy/fetch-media.sh`
เปลี่ยนชื่อและก็อปให้ โดยจับคู่จาก**ชื่อลำดับท่า**ที่อยู่ท้ายชื่อไฟล์
(ตารางจับคู่ id ↔ ชื่อท่าฝังอยู่ในสคริปต์ ตรงกับอาร์เรย์ `VIDEOS` ใน `index.html`)

**ก็อปจากโฟลเดอร์ในเครื่อง** — ใส่ได้หลายโฟลเดอร์ คั่นด้วย `:` ไล่หาตามลำดับที่ใส่

```sh
N="$HOME/Documents/Nora"
FROM_DIR="$N/web_ainora_video_output_9x16_logo_v2:$N/web_ainora_video_output" \
  sh deploy/fetch-media.sh
```

ชุด `9x16_logo_v2` เป็นคลิปแนวตั้ง 720×1280 มีลายน้ำ AI NORA อยู่แล้ว แต่มี **20 คลิป**
ขาดคลิปที่ 19 และ 21 (สองคลิปยาว) จึงต่อท้ายด้วยชุดเดิมซึ่งเป็นแนวนอน
สองคลิปนั้นจะดูต่างจากที่อื่นเล็กน้อย — ถ้าเจนเวอร์ชัน 9:16 มาเพิ่มแล้ว
วางลง `9x16_logo_v2` แล้วลบไฟล์ใน `assets/videos/` สองตัวนั้นก่อนรันสคริปต์ซ้ำ

**ดึงผ่าน HTTP** (ใช้ใน Jenkins ที่ไม่มีโฟลเดอร์นั้น)

```sh
sh deploy/fetch-media.sh
AINORA=http://ainora-app:8000 sh deploy/fetch-media.sh   # ชี้แอปภายใน
```

ไฟล์ที่มีอยู่แล้วจะข้ามไป รันซ้ำได้ · **ถ้าได้ไม่ครบ 22 คลิป สคริปต์จบด้วย exit 1**
เพื่อให้บิลด์ล้มตรงจุดนั้น ไม่ปล่อยให้ได้อิมเมจที่วิดีโอหายไปเงียบ ๆ แล้วไปรู้ตอนขึ้นจอหน้างาน
ปิดท้ายด้วยการพิมพ์ขนาดของแต่ละโฟลเดอร์ใน `assets/` ให้เห็นว่าจะได้อิมเมจใหญ่แค่ไหน

**เก็บวิดีโอไว้ใน repo** — `.gitignore` เปิดให้ commit ไฟล์ใน `assets/` ได้แล้ว
หลังรันสคริปต์เสร็จ

```sh
git add assets/videos && git commit -m "เพิ่มวิดีโอ 22 คลิป (9:16 มีลายน้ำ)"
```

CI จะ build ได้จาก repo ตรง ๆ โดยไม่ต้องพึ่งเครื่องใครหรือเน็ต (คลิปรวม ~40 MB)

**คลิปแนวตั้งกับหน้าเว็บ** — คลิปชุดนี้เป็น 9:16 และยาวคลิปละ 2–3 วินาที
สไลด์รองรับให้แล้ว: กรอบวิดีโอย่อให้พอดีคลิปแนวตั้งโดยไม่ล้นกรอบ · คลิปตั้ง `loop`
วนซ้ำในหน้าเดียว · และในโหมดซิงก์หลายจอ ตำแหน่งเวลาคิดจาก `เวลา % ความยาวคลิป`
ทุกจอจึงอยู่เฟรมเดียวกันแม้คลิปสั้นกว่าเวลาของหน้ามาก

### 3.3 build และรัน

```sh
sh deploy/fetch-media.sh
docker build -t nora-exhibition:local .
docker run -d --name nora-exhibition-web -p 10096:80 nora-exhibition:local
```

| URL | ได้อะไร |
|---|---|
| `http://<host>:10096/exhibition/` | ตัวสไลด์ (ต่อ `?ultra=1` / `?wall=1` / `?panel=1\|2\|3` ได้) |
| `http://<host>:10096/exhibition/healthz` | health check |
| `http://<host>:10096/exhibition/tools/frame-picker.html` | เครื่องมือเลือกเฟรม (ของทีมงาน) |
| path อื่นนอก `/exhibition/` | 404 ทั้งหมด |

หรือใช้ compose (ไม่มี volume ไม่มีตัวแปรอะไรให้ตั้ง)

```sh
REGISTRY_NORAEXHIBITION_IMAGE=<registry>/diis-itoc/nora-exhibition \
docker compose up -d
```

**อิมเมจเดียว คอนเทนเนอร์เดียว** — ข้างในมี nginx เสิร์ฟสไลด์ และ node
รันรีเลย์คำสั่งที่ `127.0.0.1:10097` (ไม่เปิดออกนอก เข้าถึงผ่าน `/exhibition/api/` เท่านั้น)
สคริปต์ `deploy/40-relay.sh` ถูกวางไว้ใน `/docker-entrypoint.d/` ของอิมเมจ nginx
จึงถูกเรียกให้เริ่มรีเลย์เบื้องหลังก่อน nginx ขึ้นเสมอ

เคยแยกเป็นสองคอนเทนเนอร์ แล้วเจอปัญหาที่ล้วนมาจากการแยกทั้งนั้น —
bind mount ไฟล์ต้นทางที่พังเมื่อ CI agent รันในคอนเทนเนอร์ · ต้องอยู่ network
เดียวกันเพื่อให้ nginx resolve ชื่อ service เจอ · ใช้ `docker run` เปล่า ๆ ไม่ได้ ·
ต้องดูแลอีกแท็กใน registry ทั้งที่โค้ดมีไฟล์เดียว 160 บรรทัด
งานขนาดนี้ไม่คุ้ม รวมเป็นก้อนเดียวแล้วทุกข้อหายไปพร้อมกัน

ตรวจคอนฟิก nginx และรีเลย์โดยไม่ต้อง deploy (CI ทำสองขั้นนี้ให้อยู่แล้วหลัง build)

```sh
docker run --rm --entrypoint nginx nora-exhibition:local -t
docker run --rm -d --name t nora-exhibition:local && sleep 3 && \
  docker exec t wget -qO- http://127.0.0.1/exhibition/api/healthz; docker rm -f t
```

**ไฟล์เดียวจบ (ไม่ต้องมี server)** — ใช้ส่งให้คนอื่นดู หรือเปิดพรีวิวบนเครื่องตัวเอง

```sh
python3 make-standalone.py    # standalone.html — ฝังฟอนต์+โลโก้ ยังต้องมี assets/ วางข้าง ๆ
python3 make-preview.py       # preview-full.html — ฝังภาพใน assets/ ลงไปด้วย (วิดีโอไม่ฝัง)
```

### 3.4 ต่อกับ nginx ตัวหน้าของ ainora.psu.ac.th

```nginx
location /exhibition/ {
    proxy_pass http://127.0.0.1:10096;      # <— ห้ามมี / ปิดท้าย
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

**จุดพลาดที่พบบ่อย** — ใส่ `/` ปิดท้าย `proxy_pass` nginx จะตัด `/exhibition/` ออก
ก่อนส่งเข้าคอนเทนเนอร์ ซึ่งคอนเทนเนอร์ตอบเฉพาะ `/exhibition/*` ผลคือ 404 ทั้งหน้า

### 3.5 ทุก request ผ่าน nginx ทางเดียว ไม่มี fallback

ไม่มีเส้นทางสำรองในสไลด์ ทุกอย่างเป็นไฟล์ใต้ `/exhibition/` ที่ nginx เสิร์ฟเอง
ถ้าไฟล์ไหนไม่มี จะขึ้นกล่อง "อยู่ระหว่างจัดเตรียม" ตรง ๆ ไม่ไปลองที่อื่น
ตรวจแล้วว่า element ที่โหลดสื่อทั้ง 711 ตัวมีที่มาเดียว และไม่มี request
ออกนอก `/exhibition/` แม้แต่ตัวเดียว (ทดสอบด้วยการจำลองโครงไฟล์ในอิมเมจแล้วเปิดหน้า)

### 3.6 pipeline (`Jenkinsfile`)

| stage | branch | ทำอะไร |
|---|---|---|
| Prepare | ทุก branch | เก็บ git sha + ตรวจว่ามี docker บน agent |
| Lint Dockerfile | develop | hadolint (เรียกผ่าน `docker run`) |
| Verify deck | ทุก branch | เปิดสไลด์จริงด้วย Playwright ตรวจ 4 โหมด |
| Build docker image | ทุก branch | `fetch-media.sh` → `docker build` 3 แท็ก |
| Upload to registry | **main** | push `<VERSION>` `<git sha>` `latest` |
| Deploy to Production | **main** | `docker compose up -d` + curl ตรวจว่าหน้าเปิดได้จริง |

**ทุก stage รันบน `ainora-agent` และใช้ workspace เดียวตลอดบิลด์**
จงใจไม่ใช้ `agent { docker { … } }` และไม่ใช้ `parallel` เพราะสองอย่างนั้นทำให้
Jenkins เปิด workspace เพิ่ม (`…@2@tmp`) แล้วปลั๊กอิน durable-task วางสคริปต์
ในไดเรกทอรีที่คอนเทนเนอร์มองไม่เห็น จนขึ้น `process apparently never started`
เครื่องมือที่ต้องใช้คอนเทนเนอร์จึงเรียกด้วย `docker run` ตรง ๆ จาก `sh` แทน

ไม่ต้องใช้ `stash` / `unstash` อีกแล้วเพราะ workspace เดียวกันทั้งบิลด์
(เดิม stash รวม `assets/**` ~46 MB ส่งขึ้น master ทุกครั้ง)

**ถ้ายังเจอ `process apparently never started` อีก** ให้ไล่ตามนี้บนเครื่อง agent

| เช็ค | คำสั่ง |
|---|---|
| ดิสก์เต็ม | `df -h /home/jenkins` |
| `/tmp` หรือ workspace เมานต์แบบ `noexec` | `mount \| grep -E "noexec.*(tmp\|jenkins)"` |
| jenkins เขียน workspace ไม่ได้ | `sudo -u jenkins touch /home/jenkins/workspace/.probe` |
| jenkins ไม่ได้อยู่กลุ่ม docker | `sudo -u jenkins docker ps` |
| อยากได้ log ละเอียด | เพิ่ม `-Dorg.jenkinsci.plugins.durabletask.BourneShellScript.LAUNCH_DIAGNOSTICS=true` ตอนสตาร์ต Jenkins |

credential ที่ต้องมี: `CI_REGISTRY_TOKEN` (string) และตัวแปร global `REGISTRY_URL`

### 3.7 ภาพท่าบนสไลด์ประกอบคลิป

`CONFIG.POSE_SRC` เลือกที่มาได้ที่เดียว

- `'compare'` (ค่าเริ่มต้น) — ใช้ภาพท่าที่ฟื้นฟูจากตำรา มีครบแล้ว ใช้ได้ทันที
- `'frames'` — ใช้เฟรมที่ตัดจากวิดีโอ ต้องตัด 66 ภาพด้วย `tools/frame-picker.html`
  แล้ววางใน `assets/poses/` ตามชื่อ `<videoId>-<ลำดับท่าเริ่มจาก 0>.jpg` ก่อน build

## 4. เปิดใช้งานหน้านิทรรศการ

- `?kiosk=1` — ซ่อนปุ่มและคำใบ้ทั้งหมด **ใช้โหมดนี้ตอนอัดวิดีโอและตอนเปิดหน้างาน**
- `?slide=39` — เริ่มที่หน้าที่ระบุ (ใช้ตรวจงานทีละหมวด)
- คีย์: `Space` เล่น/หยุด · `←` `→` เปลี่ยนหน้า · `F` เต็มจอ · `R` กลับหน้าแรก
- เลื่อนเมาส์เพื่อเรียกแถบปุ่ม (หายเองใน 3 วินาที)
- เล่นจบหน้าสุดท้ายจะวนกลับหน้าแรกเองไม่มีที่สิ้นสุด

## 5. โหมดจอยาว 48:9 — จอ 3 จอเรียงกัน

เปิดด้วย `?ultra=1` (หรือกดปุ่ม `U` สลับสด ๆ ตอนจัดจอ)

เวทีขยายเป็น **11520×2160** แบ่งเป็น 3 ส่วน ส่วนละ 16:9 (3840×2160) พอดีจอละ 1 ส่วน

| จอ | บทบาท | แสดงอะไร |
|---|---|---|
| **ซ้าย** | เสริม | บันไดกระบวนการ 6 ขั้นตอน ไฮไลต์ขั้นที่กำลังแสดง · โลโก้ AI NORA · แถบโลโก้ผู้สนับสนุน — คนที่เดินผ่านรู้ทันทีว่ากำลังดูขั้นตอนไหนของโครงการ |
| **กลาง** | **หลัก** | สไลด์เนื้อหา เหมือนโหมดจอเดียวเป๊ะ ๆ ไม่มีอะไรเปลี่ยน |
| **ขวา** | เสริม | ป้ายกำกับนิทรรศการ — ชื่อท่า ลำดับท่า จำนวนภาพที่ใช้ ผลตรวจ ข้อควรรู้ ที่มาอ้างอิง และเลขหน้า สิ่งที่ยาวเกินกว่าจะลงจอหลักได้ |

พื้นหลัง ไล่สีทอง ภาพลายไทย และแถบ progress **พาดต่อเนื่องข้ามทั้ง 3 จอ** เป็นผืนเดียว

### ต่อจออย่างไร

**แบบที่ 1 — เครื่องเดียว จอ 3 จอ (แนะนำ)** ต่อจอทั้ง 3 เป็นเดสก์ท็อปเดียวเรียงแนวนอน
ให้ได้ความละเอียดรวม 11520×2160 แล้วเปิด

```
https://ainora.psu.ac.th/exhibition/?ultra=1&kiosk=1
```

กด `F` เต็มจอ — ทุกอย่างซิงก์กันเองเพราะเป็นหน้าเดียว

**แบบที่ 2 — แยกเครื่องต่อจอละเครื่อง** เปิดเครื่องละ URL

```
จอซ้าย   ?ultra=1&panel=1&kiosk=1
จอกลาง  ?ultra=1&panel=2&kiosk=1
จอขวา   ?ultra=1&panel=3&kiosk=1
```

แต่ละเครื่องครอปเฉพาะส่วนของตัวเองเต็มจอ (วิดีโอใน pane ที่ซ่อนถูกหยุดไว้ ไม่ถอดรหัสทิ้ง)

> หรือจะเปิด `/exhibition/` เปล่า ๆ ทั้ง 3 เครื่อง แล้วสั่งจอ 1/2/3 กับตั้งชื่อจาก
> หน้า controller ทีละเครื่องก็ได้ ผลเหมือนกันและไม่ต้องพิมพ์ URL ยาว
> เครื่องจะจำโหมดกับชื่อไว้เอง (ดูหัวข้อ 1.5)

**ทั้ง 3 เครื่องจะตรงกันเองโดยไม่ต้องเชื่อมต่อกัน** — โหมด `panel=` เปิด *โหมดซิงก์ตามนาฬิกา*
ให้อัตโนมัติ แต่ละเครื่องคำนวณจากสูตรเดียวกันว่า "เวลานี้ควรอยู่หน้าไหน วินาทีที่เท่าไรของหน้านั้น"
แล้วกระโดดไปตรงจุดนั้น รวมถึงเลื่อนวิดีโอไปวินาทีเดียวกันด้วย

- ใช้นาฬิกาเครื่อง (NTP) เป็นตัวอ้าง — macOS/Windows ปกติเพี้ยนกันไม่เกินหลักสิบมิลลิวินาที
- เปิดเครื่องใหม่กลางทาง จะกระโดดเข้าจังหวะที่ถูกต้องเองทันที ไม่ต้องกดอะไร
- ปุ่มเลื่อนหน้าถูกปิดในโหมดนี้ (เพราะนาฬิกาจะดึงกลับ) กด `Space` หยุดดูได้ พอเล่นต่อจะเข้าจังหวะเอง
- สั่งทับได้ด้วย `?sync=1` / `?sync=0`

> **ไม่ต้องเตรียมไฟล์อะไรเพิ่มเพื่อให้ซิงก์** เพราะเวลาแต่ละหน้าเป็นค่าคงที่ในตาราง `CONFIG.DWELL`
> ทุกเครื่องจึงได้ไทม์ไลน์เดียวกันเสมอ (`assets/durations.json` จาก `frame-picker.html`
> เก็บไว้เป็นข้อมูลอ้างอิงความยาวคลิปเท่านั้น ไม่ได้ใช้กำหนดเวลาแล้ว)

### ทุกหน้ายังใช้ได้บนจอเดียว

ทุกหน้าเก็บเลย์เอาต์ 16:9 ไว้คู่กับเลย์เอาต์ผืนกว้าง เปิดบนจอเดียว (ไม่ใส่ `?ultra=1`)
ก็ได้สไลด์ที่สมบูรณ์ครบ 86 หน้าเหมือนกัน

### จัดวางและตรวจงาน

- `?seam=1` ขึ้นเส้นทองคั่นรอยต่อจอ ใช้ดูว่าเนื้อหาตกขอบจอไหนไหม (ใช้กับโหมดแบ่ง 3 จอ)
- `?ultra=1&slide=39` ตรวจทีละหน้า
- เนื้อหาทุกจอเว้นขอบใน 150px จึงไม่โดนขอบจอ (bezel) กิน

## 6. อัดเป็นวิดีโอ 4K

สไลด์วาดบนเวที 3840×2160 จริง แล้วย่อให้พอดีจอ — ถ้าอัดที่ 4K จะได้ความคมเต็มพิกเซล

1. ตั้งความละเอียดจอ/หน้าต่างเป็น 3840×2160
2. เปิด `https://ainora.psu.ac.th/exhibition/?kiosk=1` แล้วกด `F`
3. อัดหน้าจอที่ 3840×2160 (QuickTime / OBS) — ความยาวรวมประมาณ 8–10 นาที
   ขึ้นกับความยาววิดีโอแต่ละคลิป
4. กด `R` ก่อนเริ่มอัด เพื่อให้เริ่มจากหน้าแรกพอดี

> เสียงในวิดีโอถูกปิดไว้ (`muted`) เพราะเบราว์เซอร์บล็อกการเล่นอัตโนมัติที่มีเสียง
> ถ้าจะใส่เสียงประกอบ แนะนำใส่ตอนตัดต่อหลังอัด

## 7. ปรับแต่งที่ใช้บ่อย

แก้บล็อก `CONFIG` ที่ต้นไฟล์ `index.html`

```js
SEC_COMPARE   : 3,     // วินาที/หน้า หมวดเปรียบเทียบภาพ
SEC_VIDEO_MAX : 20,    // เพดานเวลาหน้าที่มีวิดีโอ
SEC_VIDEO_DEF : 8,     // เวลาสำรองถ้าอ่านความยาววิดีโอไม่ได้
SHOW_DIVIDERS : true,  // ปกหมวด
ULTRA         : false, // true = เปิดโหมดจอยาว 48:9 เป็นค่าเริ่มต้น
ANIMATE       : true   // false = ปิดอนิเมชันทั้งหมด
```

ตาราง `POSE_IMG` คือการจับคู่ "ชื่อท่าในชื่อวิดีโอ → ไฟล์ภาพท่า" อ้างจาก
`README-การจับคู่.md` ใน Drive (ยึดท่าทางในภาพ ไม่ยึดชื่อไฟล์) ใช้เป็น **ตัวสำรอง**
เมื่อยังไม่มีเฟรมใน `assets/poses/` — ยังไม่ได้จับคู่ 3 ชื่อ:
**ท่าเทวดา, ท่าพนมมือ, ท่าจีบปรกหน้า**
ถ้าใช้ `frame-picker.html` ตัดเฟรมครบแล้ว ทั้ง 3 ชื่อนี้ก็จะมีภาพเอง ไม่ต้องจับคู่
